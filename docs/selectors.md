# Selector Convention — `data-wpt` Attributes

## Why

Journey templates need stable, reliable selectors that survive:
- Elementor layout changes
- Theme updates
- Plugin version bumps
- Class renames and refactors

CSS classes and element IDs generated by Elementor and plugins are fragile. The `data-wpt` attribute is added explicitly by the developer and exists only for testing — it changes only when you deliberately change it.

## How to add `data-wpt` in Elementor

1. Open the widget in Elementor
2. Click the **Advanced** tab
3. Find the **Attributes** panel
4. Add: **Key** = `data-wpt`, **Value** = your chosen name (e.g. `contact-form-submit`)
5. Save

Requires **Elementor Pro**.

## Naming convention

Use kebab-case. Be descriptive but concise.

| Element | Value |
|---|---|
| Contact form submit button | `contact-form-submit` |
| Cookie consent dismiss button | `cookie-dismiss` |
| Product filter widget | `product-filter` |
| Search input | `search-input` |
| Member dashboard wrapper | `member-dashboard` |
| Course list container | `course-list` |

## Selector priority order

Use the highest-stability option available:

1. `[data-wpt="..."]` — **preferred** — added during feature build
2. `page.getByRole(...)` — ARIA roles, e.g. `getByRole('button', { name: 'Submit' })`
3. `page.getByLabel(...)` — for form fields with visible labels
4. WooCommerce-owned classes — `.single_add_to_cart_button`, `.wp-block-woocommerce-checkout`
5. Plugin-specific IDs/classes — acceptable when stack is consistent
6. Elementor-generated classes — **avoid** — fragile

## When to add `data-wpt`

Add a `data-wpt` attribute when building any feature that has a testable interactive element:

- Submit buttons on forms
- Dismiss/accept buttons on cookie banners
- "Add to cart" or custom purchase buttons
- Member portal containers
- Filter controls
- Any element a journey template will click or assert on

This is part of building the feature, not a separate QA step. It takes ~10 seconds per element.
